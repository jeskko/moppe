# Nokia R40 (RC40 / RD40)

Nokia R40 series trunked mobile radio (1992-2000): RC40 150/230 MHz,
RD40 450 MHz, 25 W, systems AC-2, MPT1327 and Traxys. Hams use it on
70 cm through the service mode and the five "simplex channels"
(PE1BVU, PA4KW/.540 group). There is **no community firmware**: OH5NXO's
`R40/` is a bring-up skeleton (`main: bra main`) with working drivers
for the bus devices. The emulator runs the **original Nokia firmware**;
later it can be the target for a ham firmware.

Research and emulator 2026-10-05. Facts marked (M) are from the manuals, (F) from the
firmware ROM, (X) from OH5NXO's sources; "checked" means checked
against the source in this session.

## Status (2026-10-05)

**The emulator runs the original firmware** (moppe-emu `r40.c`,
`h8500.c`, `h8532.c`; `make -C emu test-r40`; details and limits in
`emu/notes/r40.md`). RC40 Cr 13.04 on an empty NV RAM shows "Self test",
then "Service necessary / Error 6" (own subscriber number lost, as the
manual says for lost NV). With the CU43PROG service key and PWR held it
enters the LOCAL mode; PE1BVU's 70 cm procedure (tests 18, 16, 15,
10-12) runs as documented, the synthesizers tune 435 MHz correctly, and
parameter programming stores simplex channels. Narrative:
[r40-history.md](r40-history.md).

Open, in order of weight:

1. **Only one clean ROM.** `Cr1506.bin` (Cr 15.06-1, 23.08.1996, the
   MPT build) went through a **text code-page round trip**, DOS CP850 →
   Windows-1252 → CP850 (best fit), not a bad EPROM read: the 34 byte
   values that never occur in it (0f 14 15 b0-b4 b9-bc bf c0-c5 c8-ce
   d5 d9-dc df f2 fe) are exactly the CP850 characters with no 1252
   equivalent, plus the ☼ ¶ § glyphs of 0F/14/15. All eight data bits
   toggle normally. Aligned against Cr 13.04 code: box drawing became
   `+` `-` `¦`(DD), ☼→¤(CF), ¶→F4, §→F5, ı(D5)→`i`, ▀(DF)→¯(EE),
   ≥(F2)→`=`. Every target value also occurs legitimately, so the
   damage (~9 % of the bytes, by Cr 13.04's statistics) can't be undone
   mechanically; a repair would be per-byte, guided by disassembly and
   Cr 13.04. Usable ROM: RC40 **Cr 13.04-0** (06.08.1993, AC-2),
   `rc40_rom/ABSBIN`.
2. **Normal mode** hunts with the TX synthesizer and never tunes the RX
   one; the simplex-channel dialling of the MPT builds is not found.
3. **Trunking.** Normal mode wants an AC-2/MPT1327 control channel over
   the FX429 (modelled at byte level only).
4. **Unknown pin:** the synthesizer lock input "TX OFF" (SP pin 8).
   The external watchdog kick is P9.0 (below).

## Ham firmware: what is known and what is not (2026-10-05)

MVP wanted: VFO with duplex split, memory channels, VFO and memory
scan, settings (squelch etc.), CTCSS encode if the hardware allows.

Known well enough to write: memory map, interrupts, PCF8584 + CU43
(LCD with our own font, keypad except ALPHA/handset/HF/F1, lights),
PLL (any 6.25 kHz channel from 400 MHz, RX = f + 45 MHz, TX parked
+62.5 kHz until PTT; loaders 0x2F674/0x2F6F5/0x2F831), TX ON (OUT1.0),
PTT (P7.3/FTI3), RSSI (AN0), noise squelch (AN1), power-off (4094),
NV RAM (battery SRAM, plenty of room), the watchdog kick
(`watchdog_kick` 0x1CE91: P9.0 high for a few µs, then the WDT reload
A57F/5A00), and OH5NXO's drivers for all bus devices.

Gaps, in order of risk:

1. **CTCSS encode: hardware unknown.** The only tone source into the TX
   path is TMO (8-bit timer) → SIGN → the Fii switch (IC41 bit 5) →
   summing amplifier, built for the 3114 Hz ARTS tone. After it come a
   6th-order low-pass and a high-pass (C342/R470/R434, "attenuates lower
   frequencies"), and a PLL-modulated VCO may suppress sub-audio too.
   Whether 67-250 Hz reaches the carrier needs the schematic values or
   a deviation meter on a real radio. CTCSS decode has no path at all
   (no AF to the A/D found). The RD540 article: "no CTCSS in the sets".
2. **Toolchain.** No C compiler for the H8/500 is available today.
   Historically: Cygnus' GCC 2.7-96q3 had an `h8500-hms` target (never
   in FSF GCC: 2.7.2.3 and 2.8.1 on ftp.gnu.org have only h8300,
   checked; newlib still has `libc/machine/h8500`), source not located;
   IAR sold one (commercial, gone); Avocet's handled only the minimum
   modes. OH5NXO wrote asm with binutils 2.15 h8500-hms (our full build
   failed; the disassembler builds); Alfred Arnold's AS lists the
   H8/500. Realistic routes besides asm: a back end for a small
   retargetable compiler (lcc or vbcc) for a one-page "small model"
   (code in page 0, data in page 8), checked against the emulator's
   CPU core; resurrecting the Cygnus GCC if its source turns up; or
   Forth on an asm kernel.
3. **Calibration tables.** A ham firmware should reuse Nokia's factory
   data in NV rather than ask for recalibration: RX front-end tuning
   per 1 MHz (test 36, MC144111 RFC; defaults at 0x6C.. after 190002),
   TX power (20x, TPC DAC), deviation correction per channel (IC27 via
   the 4094 DEV bits), squelch levels (33/34). Offsets and formats are
   not mapped yet: emulator NV diffs plus the Nokia code in Ghidra.
4. **4094 bit meanings disagree** between OH5NXO's `PINS` and the
   board description (IC40/IC41: volume, PA, deviation, Fii, cue tones).
   Settle with the Nokia firmware's SR events in the emulator
   (volume keys, PTT, tones), then on hardware.
5. **Timing:** PLL lock time and the lock input ("TX OFF", pin
   unknown) set the scan rate and TX keying; Nokia steps its hunt at
   ~50 channels/s, a first guess. RX/TX switching order (mute, TX ON,
   PA ramp) can be copied from the Nokia firmware's events.
6. **Hardware for testing:** nothing checked on a real R40 yet
   (banked ROM decode, keys, CTCSS path).

## Hardware

**CPU** (M, checked in the board description): Hitachi H8/532, mode 3
(expanded maximum), 16.128 MHz crystal, φ = 8.064 MHz, output on P1.0.
The firmware uses only registers 0xFF80-0xFFFF (F), consistent with the
H8/532. Interrupt vectors are 4 bytes (page word + PC word), DTC area
0x100-0x17f unused (all FF).

**Memory map** (M p.4 of the board description, checked; agrees with X and F):

| Address | Device |
|---|---|
| 0x00000-0x7FFFF | EPROM IC53, 27C020 used (256 KB) |
| 0x80000-0x83FFF | NVRAM (battery-backed SRAM; two 8 KB pages, OUT0.3 RAM PAGE, P9.2 also selects; firmware keeps both at 0). The stack lives here (TP = 8, SP from 0x1680). P9.2 must read 0 while still an input after reset: the first PJSR pushes before P9DDR is set (emulator, 2026-10-05) |
| 0x88000-0x8FFFF | SRAM 32 KB |
| 0x90000-0x9FFFF | SRAM reserved (not used by the firmware, F) |
| 0xA0000 | FX429 FFSK modem (reads need a wait state: WCR 0xF1, F and X) |
| 0xA8000 | OUT0 latch 74HC374: D0 DAC CS, D1 RTC CS, D2 FX803 CS, D3 NV page, D6/D7 TMCI clock select 2.016 MHz / 504 kHz (X) |
| 0xB0000 | OUT1 latch: D0 TX ON, D1-D3 4094 strobes, D4 CTS, D5 DSR, D6 DCD, D7 RI |
| 0xB8000/1 | PCF8584 I2C controller (data, control), fclk 4.032 MHz |
| 0xC0000 | Security PROM IC35, 256x4, **not mounted** (M); the firmware never loads page 0xC (F) |

Each window is 32 KB (decoder IC51). The firmware runs with on-chip RAM
**disabled** (RAMCR = 0 at reset, 0x7F later) and executes ROM at
0xFB81-0xFDF8 in page 0 (F). OH5NXO's start.s enables it instead.

**Ports** (M + X): P1: .0 φ out, .2 serial bus CLK, .3 serial bus DATA
(also DS1202 I/O), .4 FX803 data in, .5 /IRQ0 (level: control head
keys via PCF8574 INT), .6 /IRQ1 (edge: FX429 and FX803), .7 TMO (tones,
final Hz = TMO/8). P7: .0 TMCI (2.016 MHz or 504 kHz), .1 PLL SD, .2 SRE
(RX PLL strobe; but see below), .3 /PTT (FRT3 capture), .4 PLL CLK,
.5 7875 Hz (FRT2), .6 STE (TX PLL strobe). The firmware sets P7DDR = D2,
so P7.2 is an input: it is FTI2, the PCF8584 INT; SRE is P7.7, as in
OH5NXO's `pll.s` (X; the RX loads in the emulator come on P7.7). P8: AN0 RSSI, AN1 SQ, AN4 +VB, AN2/3/6/7 digital
inputs (RTS, DTR, IGN, PTT_HF?). P9: .2 NV select, .5-.7 SCI TXD/RXD/SCK.
PCF8584 interrupt goes to FRT2 input capture (ICI2 vector), not IRQ0 (M).

**Serial-bus devices** (X): MC144111 4x6-bit DAC (RFC receiver tuning,
TPC TX power), DS1202 RTC (burst read 0xBF), FX803 (CCIR/DTMF, option),
three 4094 shift registers for audio switching, volume and deviation.

**PLL** (M + X, F): two Fujitsu MB-series chips (RX, TX) on a shared
SD/CLK with strobes SRE (P7.7) / STE (P7.6); R register 14 bits + SW
(prescaler 64/65 or 128/129) with control bit C=1, N/A with C=0. The
chips count the VCO's **second harmonic** (OH5NXO's `pll.s`). Cr 13.04
uses SW = 0 (128/129), R = 1024 (12.5 kHz at the 12.8 MHz reference),
so VCO = (128 N + A) x 6.25 kHz; it shifts the R word once and strobes
both chips. RX VCO = f + 45 MHz; TX is parked A + 10 (+62.5 kHz) and
loaded with A on PTT (emulator: 435 MHz in service mode gives RX 600/0,
TX 543/96, parked 543/106).
Channel numbers: physical channel = (f − X) / 6.25 kHz, X = 400 MHz for
the RD40 (checked against PE1BVU's table: 430.5375 MHz → 4886). The
0-channels are set by test 18 (1 = TX, 2 = RX, in 6.25 kHz units:
64000/71200 = 400/445 MHz; the RX side is offset by the 45 MHz IF).

**Firmware use of the CPU** (F, ABSBIN): vectors in use are reset,
traps, NMI, IRQ0 (0x313ba), IRQ1 (0x3105a), OCIA1, ICI2 (PCF8584),
OCIA2, ICI3 (PTT), SCI ERI/RXI/TXI. SCI BRR 0x19. WDT run as watchdog
(0xA55F/0x5A00). FRT1-3, the 8-bit timer, A/D and PWM1 are touched.
Priorities: IRQ0 1, IRQ1 4, FRT1 7, FRT2 2, FRT3 2, TMR 2, SCI 5, ADC 2.
Device writes go via EP and RAM shadow copies; slow FX429 reads through
one helper at 0x31398. No unknown device addresses.

## Control head (CU42 / CU43)

No CPU: all I2C behind the PCF8584 (M, X, checked in CU43_description).

| Addr | Chip | Use |
|---|---|---|
| 0x40 | PCF8574 IC120 | outputs: P7 mic mute, P6 mic select, P5 hands-free, P4 CALL, P3 ON, P2 TX LED, P1:0 HF level |
| 0x42 | PCF8574 IC190 | inputs, drives INT: P6 ON/OFF (0 = pressed), P5 HOOK, P4-0 key columns |
| 0x44 | PCF8574 IC200 | P7 display light, P6 head type strap (input; 0 = CU43, F), P5 key light, P4-0 key rows |
| 0x78 | PCF8578 (sub 0) + 3x PCF8579 (sub 1-3) | LCD 120x23, mux 1:24: text rows of 20, 24, 24 chars (5x7) plus two icon rows. The manual names the parts the other way round; the firmware's writes (PCF8578 columns at X 24-39, then 40 per PCF8579) fit OH5NXO's version |
| 0x74 | ? (not in the CU43) | 8-character segment display: with IC200 P6 = 1 the firmware writes `80` + 8 bytes there and keeps the dot-matrix blank (F, emulator) |
| 0x4A | ? | written FF at start-up (another head's expander?), not acked by a CU43 |
| 0x48 | PCD3312 (logic board, X) | DTMF generator |
| 0xA0 | 24C02 IC260 | maintenance key, only in the red CU43PROG |

**Service key:** the 24C02 holds `3A 01 F0` and zeros (PE1BVU, checked
against the page). Holding PWR at power-on until "Self test" enters the
LOCAL (service) mode, which reads this ID over I2C (the firmware reads two
bytes, `3A 01`; emulator).

**Display:** the firmware draws with its own 5x7 font (ROM 0x2E34, 5
bytes per character from space; bit 0 of each column unused), 24
five-column cells per row. The top row's glass shows 20 characters:
cells 2, 9, 14 and 21 are gaps (emulator: 2 and 9 from "Self test", 21
from the service display's frequency, 14 by symmetry).

**Keypad** (emulator, each matrix position pressed in LOCAL mode; row =
IC200 bit, column = IC190 bit):

| row \ col | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 0 | RCL/STO | 3 | 2 | 1 | ? |
| 1 | ? | 6 | 5 | 4 | OK |
| 2 | FNC | 9 | 8 | 7 | UP |
| 3 | CLR | # | 0 | * | DOWN |
| 4 | ? | ? | ? | ? | ? |

FNC then STO enters parameter programming; UP/DOWN change test values
and step parameters; RCL steps test 36. The CU43 also has ALPHA, the
handset key, HF and F1 (instruction manual): among the `?`; (4,4)
clears a dial entry in normal mode.

OH5NXO's CU42 map in `cu42.s` is this mirrored and shifted; PWR is
IC190 P6, outside the matrix.

## NV RAM

(F + emulator, Cr 13.04.) Offsets within the 16 KB NV window
(0x80000). Two checksummed copies at 0x0000 and 0x2000 in the half
selected by P9.2 = 1; the half with P9.2 = 0 holds the working copy at
the same offsets (edited in service mode, committed to both copies by
`*`) and the stack. The block table at ROM 0x36966 (routine 0x3689c,
args start, length, checksum byte) gives 11 blocks; each checksum byte
is NOT(sum of the block), so the block including it sums to 0xFF:

| Block | Checksum | Contents found |
|---|---|---|
| 0x000-0x12A | 0x12B | RF set-up (below) |
| 0x12C-0x134 | 0x135 | not written yet |
| 0x136-0x1CA | 0x1CB | cold-start defaults |
| 0x1CC-0x3F0 | 0x3F1 | "British Gas Northern" at 0x216 (cold-start text), 1234 at 0x3EE (the parameter code?) |
| 0x3F2-0x486 | 0x487 | own number (parameter 800) near 0x482 |
| 0x488-0xA6C | 0xA6D | parameter records, 6 bytes each from 0x48E (parameter 001): RX word, TX word, `st` word; 030-034 = simplex channels 1-5 at 0x53C; FFFF = unused |
| 0xA6E-0xE87 | 0xE88 | |
| 0xE89-0x10A8 | 0x10A9 | |
| 0x10AA-0x129D | 0x129E | |
| 0x129F-0x15FA | 0x15FB | |
| 0x15FC-0x1673 | 0x1674 | not written yet |

RF set-up in the first block (service tests; words big-endian):

| Offset | Test | Value |
|---|---|---|
| 0x56 / 0x58 | 10 | band low, two equal words (RX / TX assumed), physical channel (4800 = 430.0 MHz) |
| 0x5A / 0x5C | 11 | band middle |
| 0x5E / 0x60 | 12 | band high |
| 0x63 | 15x | band (0x80 = D) |
| 0x64 (long) | 18 1 | TX 0-channel, 6.25 kHz units (64000) |
| 0x68 (long) | 18 2 | RX 0-channel (71200) |
| 0x71 | 15x | spacing (1 = 12.5 kHz) |
| 0x128 | 16 | 1 semiduplex, 2 simplex (shift digits not decoded) |

Tests 10-12 store (f / 3.125 kHz) mod 2^16 if the 0-channels are unset:
run test 18 first, as PE1BVU does.

## Service mode

From the type-approval file p.17-41, the 1996 manual p.94-124 and
PE1BVU. The top row shows spacing, logical channel, physical channel
and RX frequency (e.g. `1 448 04800 43000000`), then `rsl` and its
0-255 value; PTT shows TX values. Tests are digits + OK: 10/11/12 band
calibration frequencies, 15x spacing/band, 16 simplex/duplex and shift,
17x/190002 copy default tables from ROM, 18 0-channels, 20x TX power,
31-34 squelch, 36 RX tuning, 40-44 audio, 47 RTC, 5x CCIR/modem/DTMF,
61-65 battery, DAC, A/D, port write/read, 66 safety code, 70 + `1234` FNC STO
parameter programming (shows parameter 700 first; UP steps; 030-034
the simplex channels: rx, tx and in Cr 13.04 an `st` value, each
entered with FNC STO; 7xx system parameters; 800 own number), `*`
leaves. 172 then 190002 load the D-band tuning defaults (clears
Error 11) and overwrite the 10-12 calibration words, so 10-12 come
after. 31/32 (squelch delays) are factory tests and are not stored in
NV (manual; the emulator agrees: FNC STO writes nothing), unlike
33/34. Error codes: 1 catalogue, 2 status texts, 3 data messages, 4
system information, 5 adjustment parameters, 6 own number, 9 system
parameters, 10 channel table, 11 default adjustment parameters.
Normal mode: `*55*n#` selects simplex channel n, `#55#` leaves (PE1BVU
writes `*55*00n#` for his MPT radios). In Cr 13.04 (Ghidra + emulator)
n is a **parameter record number** (1-251, so PE1BVU's 030-034 are
`*55*30#` .. `*55*34#`), and the record must have bit 3 set in its
`st` byte (enter `st` 008): the check is 0x34ADB, "Invalid channel"
otherwise. The normal-mode entry starts with `999`, which spoils the
code: press CLR first. Simplex shows "Simplex channel: 030 / Squelch
ON  Mode OPEN"; the RX VCO goes to f + 45 MHz, PTT transmits on f, and
the TX sweep stops. The dial codes are a table of strings (`*2*`,
`*0#`, `*0nn#`, `*41*`, `#41`, `#45`, `*411*` ... `*55*`, `#55`,
`#56`, `*56`, `*52`, `#52`, `*8*`, `*9*`, `*11*`, `*31*`) at ROM
0x62EA, copied with 0x5EE2-0x63CA to 8:1680 at reset; their handlers
sit around 0x8AFE-0xA516. Texts "Functions for simplex / and open
channel", "Simplex operation", "Exit simplex operation" suggest a menu
route too (not tried).

Parameters: `reference/cq3meter/r40_params.txt` (decoded from AMAN's
`AMAN_PAR.AP0`; columns inferred) and the Nokia parameter reference
`AMAN43.ocr.txt`. A real Cr15.06 radio's values in
`r40_cr1506_param_dump.txt` (MPT build, so only a guide for Cr13.04).

## PC programming (AMAN)

Nokia AMAN: DOS 2.17 ("R40 MPT sw. Cr15", Sentinel dongle on LPT1) and
Windows 3.13 (Hardlock dongle; cracked copies in the bundle). Needs the
service head. The Windows build talks through Nokia LN32.DLL
("LocalNet", M-Bus/"M2"; inferred from strings) and names the radio's
RPC functions: `hw_eeprom_field_read/write(word)`, `ts_data_read/write`,
`ui_data_read/write`, `hw_lcd_write_string`, `hw_port_write`,
`dev_local_start` (checked in the exe). No frame format or baud rate
found. Not needed for a first emulator.

Firmware versions (AMAN43): AC-2 13.07, Traxys 14.07-01, MPT 15.07-01
(plus 14.17/15.17 Spanish, 14.27 French); units seen with Cr 13.04-5,
13.05-0, 13.05-2. The version string is at ROM 0x180.

## Tools

- **Ghidra** (12.1.2, `/opt/ghidra`): the community H8/500 SLEIGH module
  https://github.com/OZVR4/Ghidra-H8-Processor (H8/539F, maximum mode;
  cloned to `reference/ghidra-h8`) plus moppe's files in
  `tools/ghidra-r40/`: `install.sh` (user extension, applies
  `ghidra-h8.patch`, adds language `H8:BE:32:H8532` from
  `gen_pspec.py`: H8/532 registers and vectors), `coverage.py`
  (emulator run → executed-code map), `import.sh` (headless project
  `reference/ghidra-r40/R40`, gitignored: `ImportR40.java` memory map,
  page context DP/EP/TP = 8, BR = FF, vectors and known names;
  `SeedCoverage.java` disassembles everything the emulator executed),
  `Decompile.java` (decompile / `xref:NAME` from the command line),
  `check_lengths.py` and `check_decoder.py` (decoder checks).
  Patch: `jmp @aa:16` read memory instead of jumping (reset's jump to
  the main loop was lost), SUBS with a general EA was missing. Checked:
  every instruction of a full linear sweep (89 955, data included)
  decodes at binutils' length except binutils' own errors (RTD #xx:8,
  word STC/LDC SR) and invalid encodings; all 8 035 instructions the
  emulator executes are decoded (47 788 instructions, 650 functions).
  Cross-references and names are reliable; the decompiler's C is noisy
  (PJSR return-address pushes show as stack stores, many
  `extraout_` values) but readable.
- **Disassembler:** binutils 2.15 from `reference/oh5nxo/mods/hc11/`
  has the h8500 target. A full build fails; a standalone harness of
  `h8500-dis.c` + `dis-buf.c` + `dis-init.c` works
  (`reference/r40work/build.sh`, `dis.c` linear sweep, `dis2.c`
  addresses on stdin). The stock opcode table is wrong:
  `mov:g.w #imm8,<ea>` is one byte too long, `cmp:g.w #imm8,<ea>` is
  missing, 0x0A (RTE) is not decoded. The fixes are in
  `reference/r40work/h8500-opc.patch`; `disa` has the bugs (1937 unknown
  instructions, desyncs). Also wrong and not patched: `rtd` lists 0x14
  for the 16-bit form too (the manual: 0x14 #xx:8, 0x1C #xx:16).
- **MAME** `src/devices/cpu/h8500/` (BSD-3-Clause): executing core
  generated from `h8500.lst` by `h8500make.py`, plus h8532, FRT and
  interrupt controller devices. Some opcodes still `fatalerror`. Read as
  a cross-check for moppe-emu's own core (the EP:DP pair moved by byte
  STC/LDC EP on the stack comes from it).
