# Nokia R40 (RC40 / RD40): emulator feasibility

Nokia R40 series trunked mobile radio (1992-2000): RC40 150/230 MHz,
RD40 450 MHz, 25 W, systems AC-2, MPT1327 and Traxys. Hams use it on
70 cm through the service mode and the five "simplex channels"
(PE1BVU, PA4KW/.540 group). There is **no community firmware**: OH5NXO's
`R40/` is a bring-up skeleton (`main: bra main`) with working drivers
for the bus devices. An emulator would first run the **original Nokia
firmware**, and later serve as the target for a ham firmware.

Research 2026-10-05. Facts marked (M) are from the manuals, (F) from the
firmware ROM, (X) from OH5NXO's sources; "checked" means checked
against the source in this session.

## Verdict

Enough material for an emulator that boots the RC40 Cr 13.04 ROM into
normal and service ("LOCAL") mode with an emulated CU43 / CU43PROG
control head. The memory map and device addresses agree in three
independent sources (manual, OH5NXO's PINS, firmware cross-reference).
The work is mostly new code: an **H8/500 CPU core** (nothing in moppe-emu
fits; MAME's BSD-3 core is a reference) and the H8/532 on-chip
peripherals. Gaps, in order of weight:

1. **Only one clean ROM.** `Cr1506.bin` (Cr 15.06-1, 23.08.1996, the
   MPT build) is damaged: 34 byte values never occur in it (0f 14 15
   b0-b4 b9-bc bf c0-c5 c8-ce d5 d9-dc df f2 fe; ABSBIN uses all 256,
   checked), apparently a many-to-one byte substitution. Its strings
   are intact, its code is not. The ZIP copy is identical. Usable ROM:
   RC40 **Cr 13.04-0** (06.08.1993, AC-2), `rc40_rom/ABSBIN`.
2. **NVRAM layout unknown.** No source gives byte addresses (the AMAN
   R40 parameter files have no address column). The firmware cold
   starts by itself when the RAM signature at 0x8bc95 is not 0x55/0x5a
   (F), so an empty NVRAM works; the layout can be learned by running
   service tests in the emulator and watching NVRAM writes.
3. **Trunking.** Normal mode wants an AC-2/MPT1327 control channel over
   the FX429 FFSK modem. Without one it will hunt; service mode and the
   simplex channels need no network. A control-channel simulator is
   optional later work.
4. **Datasheets still missing:** PCF8578/PCF8579 (LCD driver RAM and
   modes; needed for the display) and FX429. PCF8574 is trivial.
5. **Unknown pins:** the external watchdog IC57 kick line (MR, 4 s) and
   the synthesizer lock input "TX OFF" (SP pin 8) are not mapped to MCU
   pins in the text; find them by running the firmware.
6. **Licence:** the Nokia ROM is proprietary. It cannot go into the
   public emulator repo; tests need a user-supplied ROM path.

## Hardware

**CPU** (M, checked in the board description): Hitachi H8/532, mode 3
(expanded maximum), 16.128 MHz crystal, φ = 8.064 MHz, output on P1.0.
The firmware uses only registers 0xFF80-0xFFFF (F), consistent with the
H8/532. Interrupt vectors are 4 bytes (page word + PC word), DTC area
0x100-0x17f unused (all FF).

**Memory map** (M p.4 of the board description, checked; agrees with X and F):

| Address | Device |
|---|---|
| 0x00000-0x7FFFF | EPROM IC53, 27C020 used (256 KB) |
| 0x80000-0x83FFF | NVRAM (battery-backed SRAM; two 8 KB pages, OUT0.3 RAM PAGE, P9.2 also selects; firmware keeps both at 0) |
| 0x88000-0x8FFFF | SRAM 32 KB |
| 0x90000-0x9FFFF | SRAM reserved (not used by the firmware, F) |
| 0xA0000 | FX429 FFSK modem (reads need a wait state: WCR 0xF1, F and X) |
| 0xA8000 | OUT0 latch 74HC374: D0 DAC CS, D1 RTC CS, D2 FX803 CS, D3 NV page, D6/D7 TMCI clock select 2.016 MHz / 504 kHz (X) |
| 0xB0000 | OUT1 latch: D0 TX ON, D1-D3 4094 strobes, D4 CTS, D5 DSR, D6 DCD, D7 RI |
| 0xB8000/1 | PCF8584 I2C controller (data, control), fclk 4.032 MHz |
| 0xC0000 | Security PROM IC35, 256x4, **not mounted** (M); the firmware never loads page 0xC (F) |

Each window is 32 KB (decoder IC51). The firmware runs with on-chip RAM
**disabled** (RAMCR = 0 at reset, 0x7F later) and executes ROM at
0xFB81-0xFDF8 in page 0 (F). OH5NXO's start.s enables it instead.

**Ports** (M + X): P1: .0 φ out, .2 serial bus CLK, .3 serial bus DATA
(also DS1202 I/O), .4 FX803 data in, .5 /IRQ0 (level: control head
keys via PCF8574 INT), .6 /IRQ1 (edge: FX429 and FX803), .7 TMO (tones,
final Hz = TMO/8). P7: .0 TMCI (2.016 MHz or 504 kHz), .1 PLL SD, .2 SRE
(RX PLL strobe), .3 /PTT (FRT3 capture), .4 PLL CLK, .5 7875 Hz (FRT2),
.6 STE (TX PLL strobe). P8: AN0 RSSI, AN1 SQ, AN4 +VB, AN2/3/6/7 digital
inputs (RTS, DTR, IGN, PTT_HF?). P9: .2 NV select, .5-.7 SCI TXD/RXD/SCK.
PCF8584 interrupt goes to FRT2 input capture (ICI2 vector), not IRQ0 (M).

**Serial-bus devices** (X): MC144111 4x6-bit DAC (RFC receiver tuning,
TPC TX power), DS1202 RTC (burst read 0xBF), FX803 (CCIR/DTMF, option),
three 4094 shift registers for audio switching, volume and deviation.

**PLL** (M + X): two Fujitsu MB-series chips (RX, TX) on a shared SD/CLK
with strobes SRE/STE; R register 14 bits + SW (prescaler 64/65 or
128/129) with control bit C=1, N/A with C=0; reference 12.5 kHz.
Channel numbers: physical channel = (f − X) / 6.25 kHz, X = 400 MHz for
the RD40 (checked against PE1BVU's table: 430.5375 MHz → 4886). The
0-channels are parameters 321/322 (band D 64000/71200 = 400/445 MHz; the
RX side is offset by the 45 MHz IF).

**Firmware use of the CPU** (F, ABSBIN): vectors in use are reset,
traps, NMI, IRQ0 (0x313ba), IRQ1 (0x3105a), OCIA1, ICI2 (PCF8584),
OCIA2, ICI3 (PTT), SCI ERI/RXI/TXI. SCI BRR 0x19. WDT run as watchdog
(0xA55F/0x5A00). FRT1-3, the 8-bit timer, A/D and PWM1 are touched.
Priorities: IRQ0 1, IRQ1 4, FRT1 7, FRT2 2, FRT3 2, TMR 2, SCI 5, ADC 2.
Device writes go via EP and RAM shadow copies; slow FX429 reads through
one helper at 0x31398. No unknown device addresses.

## Control head (CU42 / CU43)

No CPU: all I2C behind the PCF8584 (M, X, checked in CU43_description).

| Addr | Chip | Use |
|---|---|---|
| 0x40 | PCF8574 IC120 | outputs: P7 mic mute, P6 mic select, P5 hands-free, P4 CALL, P3 ON, P2 TX LED, P1:0 HF level |
| 0x42 | PCF8574 IC190 | inputs, drives INT: P6 ON/OFF (0 = pressed), P5 HOOK, P4-0 key columns |
| 0x44 | PCF8574 IC200 | P7 display light, P6 light level (also CU43/CU45 type), P5 key light, P4-0 key rows |
| 0x78 | PCF8579 IC220 + 3x PCF8578 (sub 0-3) | LCD 120x23, mux 1:24: text rows of 20, 24, 24 chars (5x7) plus two icon rows |
| 0xA0 | 24C02 IC260 | maintenance key, only in the red CU43PROG |

**Service key:** the 24C02 holds `3A 01 F0` and zeros (PE1BVU, checked
against the page). Holding PWR at power-on until "Self test" enters the
LOCAL (service) mode, which reads this ID over I2C.

## Service mode (test cases for an emulator)

From the type-approval file p.17-41, the 1996 manual p.94-124 and
PE1BVU. The top row shows spacing, logical channel, physical channel
and RX frequency (e.g. `1 448 04800 43000000`), then `rsl` and its
0-255 value; PTT shows TX values. Tests are digits + OK: 10/11/12 band
calibration frequencies, 15x spacing/band, 16 simplex/duplex and shift,
17x/190002 copy default tables from ROM, 18 0-channels, 20x TX power,
31-34 squelch, 36 RX tuning, 40-44 audio, 47 RTC, 5x CCIR/modem/DTMF,
61-65 battery, DAC, A/D, port write/read, 66 safety code, 70 + `1234`
parameter programming (030-034 the simplex channels as RX/TX physical
channel numbers, 7xx system parameters), `*` leaves, FNC STO stores.
Normal mode: `*55*00n#` selects simplex channel n.

Parameters: `reference/cq3meter/r40_params.txt` (decoded from AMAN's
`AMAN_PAR.AP0`; columns inferred) and the Nokia parameter reference
`AMAN43.ocr.txt`. A real Cr15.06 radio's values in
`r40_cr1506_param_dump.txt` (MPT build, so only a guide for Cr13.04).

## PC programming (AMAN)

Nokia AMAN: DOS 2.17 ("R40 MPT sw. Cr15", Sentinel dongle on LPT1) and
Windows 3.13 (Hardlock dongle; cracked copies in the bundle). Needs the
service head. The Windows build talks through Nokia LN32.DLL
("LocalNet", M-Bus/"M2"; inferred from strings) and names the radio's
RPC functions: `hw_eeprom_field_read/write(word)`, `ts_data_read/write`,
`ui_data_read/write`, `hw_lcd_write_string`, `hw_port_write`,
`dev_local_start` (checked in the exe). No frame format or baud rate
found. Not needed for a first emulator.

Firmware versions (AMAN43): AC-2 13.07, Traxys 14.07-01, MPT 15.07-01
(plus 14.17/15.17 Spanish, 14.27 French); units seen with Cr 13.04-5,
13.05-0, 13.05-2. The version string is at ROM 0x180.

## Tools

- **Disassembler:** binutils 2.15 from `reference/oh5nxo/mods/hc11/`
  has the h8500 target. A full build fails; a standalone harness of
  `h8500-dis.c` + `dis-buf.c` + `dis-init.c` works
  (`reference/r40work/build.sh`, `dis.c` linear sweep, `dis2.c`
  addresses on stdin). The stock opcode table is wrong:
  `mov:g.w #imm8,<ea>` is one byte too long, `cmp:g.w #imm8,<ea>` is
  missing, 0x0A (RTE) is not decoded. The fixes are in
  `reference/r40work/h8500-opc.patch`; `disa` has the bugs (1937 unknown
  instructions, desyncs).
- **MAME** `src/devices/cpu/h8500/` (BSD-3-Clause): executing core
  generated from `h8500.lst` by `h8500make.py`, plus h8532, FRT and
  interrupt controller devices. Some opcodes still `fatalerror`.
