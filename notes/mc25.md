# Mobira MC25 TVL/PTL

VHF (146-155 MHz) ARP/TVL radio, CDP1802. **Emulated since 2026-10-02**
(moppe-emu `mc25.c`, `cu41.c`; model table, evidence and limits in
`emu/notes/mc25.md`): the ham firmware mc25.asm v3.6 runs through its
README's first-time setup and normal use (entry, TX limits, PTT, CCIR
send/receive, serial keys, setup).

## Hardware (manual + firmware)

- **CPU** CDP1802E at **2.24 MHz** (firmware: "35 * 8 == 280 == 1 ms"; 2.24 MHz crystal in the parts list).
- **KL1 parts:** 27C64 EPROM (27128 also fits), 2 x TC5514 (1Kx4) RAM, X2212 256x4 NOVRAM, 2 x CDP1853 N-line decoders, CDP1863 frequency generator, 3 x 74C374 output ports, ICL8212 voltage detector, MC14504 level shifters.
- **Memory (firmware):** ROM 0000; optional serially loaded code EEPROM 4000-5FFF (`-DEEPROM` builds); RAM 8000 (1 KB); NOVRAM C000-C0FF, low nibbles (no STORE/RECALL in the firmware).
- **I/O ports** (binary N decode via CDP1853): OUT 1 display/keypad bit-bang (SDO, KEYCLK, DPYCLK, display /RST, synth P0, external alarm); OUT 2 synth divisor P1..P8 (parallel); OUT 3 volume (4 bits), TX on, earphone, squelch enable, tone; INP 4 hook, squelch, lock, program, office, 1800 Hz, CCIR EV/ARP detect (also pats the watchdog); OUT 5 CCIR TX code (TV1 IC9), CCIR RX acks, mic switch; INP 6 CCIR EV/ARP digit nibbles; OUT 7 2000/3112 Hz tones, simplex receivers, TX power.
- **Flags:** /EF1 PTT, /EF3 keypad SDI, /EF4 LOCAL.
- **Interrupt:** 1 ms timer (fixed; nothing programs it). The firmware runs display and keypad bit-bang as co-routines from it (`sep Rdpyproc`, `Rkeyproc`).
- **Synth:** RX = 2 x (62.000 MHz + n x 12.5 kHz) + 21.4 MHz; TX = 2 x (13.200 + 62.000 + n x 12.5 kHz) MHz (manual's example n = 86: RX 147.550, TX 152.550).
- **Handset CU41:** no CPU. Keys: SDI goes high while a key is held (DA); after release each CLK1 trailing edge shifts out a 0 start bit and the 8-bit code LSB first (firmware `keyproc`; code-to-key in `keytbl`). Display: 14-character VFD (NEC LD8232) plus LEDs, fed 8 bits per byte MSB first on SDO, latched at DPYCLK rise. Its controller behaves like a 16-cell cursor display: after /RST the firmware sends AF C0 FE, 14 x '8', two LED codes and the banner, then 16-byte frames (two LED cells, 14 characters) that land LEDs in cells 14-15; 0x6E is a decimal point on the previous cell. The character codes are ASCII-like with exceptions (`chrtbl`: 0 = 0x4F, 1 = 0x28, b = 0x1E, d = 0x23; C_r 0x2B, C_t 0x7B, C_n 0x4D ...); LEDs are lit by codes from `ledtbl`.
- **Hook:** INP 4 bit 0 = 1 with the handset on the hook (cradle switch pressed); PTT then sends CCIR tone 8 (1747 Hz repeater burst) instead of the mic.
- **Serial:** /EF2 is a 1200 baud **8E1** soft-UART input (mark = pin low, MobyDick's resistor/diode converter); a NUL wakes the interrupt-time receiver, which reads digits and `# * + - A T N C` ('L' = next long) until EOT. ENQ makes it send the LED byte (hex) and the display text on Q.
- **Setup:** 92# enters it, + / - walk it, T goes to its start, # leaves from there; first fields after a reset: bASEF (8 digits, e.g. 14540045), tr diFF, tr Lo, tr Hi (TX needs trlo < divisor < trhi).
- **TV1 signalling:** two CCIR decoders (EV, ARP) with 560 kHz clock, CCIR encoder IC9, 1800 Hz PLL detector, tone divider from the CPU clock (2000, 3112, 425 Hz).

## Open questions

- KL1 functional description (memory decode, interrupt source, watchdog time) is not in the manual; schematic pages exist only as images. RAM/NOVRAM mirroring and the 0.1 s watchdog are assumptions in the emulator.
- Display controller: part and command set (AF C0 FE) unknown; only the codes the firmware sends are known.
- No original Nokia TVL firmware dump (only the ham firmware).
